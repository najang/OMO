# OMO · 요구사항 분석

## 기능 요구사항 (Functional Requirements)

| ID | 분류 | 요구사항 | 우선순위 |
|----|------|----------|----------|
| FR-01 | 인증 | 회원가입 / 로그인 (소셜 로그인) | P1 |
| FR-01a | 인증 | 신규 유저 닉네임 설정 온보딩 (한글/영어 2~6자, 로그인 후 최초 1회 강제) | P1 |
| FR-02 | 알림 설정 | 알림 받을 시간대 설정 (HH:mm) | P1 |
| FR-03 | 알림 발송 | 설정한 시간에 날씨 + 옷차림 푸시 알림 발송 | P1 |
| FR-04 | 추천 | 위치 기반 날씨 조회 후 옷차림 추천 (규칙 기반) | P1 |
| FR-05 | 피드백 | 앱 진입 시 어제 옷차림 피드백 토스트 노출 | P1 |
| FR-06 | 피드백 | 추웠음 / 적당 / 더웠음 / 실내에만 있었어요 선택 | P1 |
| FR-07 | 마이페이지 | 일자별 옷차림 + 피드백 기록 조회 | P2 |
| FR-08 | 개인화 | 누적 피드백 기반 추천 보정 | P2 |
| FR-09 | 기록 | 유저가 직접 입력한 옷차림 기록 | P3 |
| FR-10 | 통계 | 월별 체감 통계 / 인사이트 리포트 | P3 |

## 비기능 요구사항 (Non-functional Requirements)

| 분류 | 요구사항 |
|------|----------|
| 성능 | 추천 API 응답 < 500ms |
| 신뢰성 | 푸시 알림 정시 발송 (±1분 이내) |
| 가용성 | 외부 날씨 API 장애 시 직전 캐시 응답 또는 graceful degradation |
| 확장성 | 유저 수 증가 시 알림 발송 워커 수평 확장 가능 |
| 보안 | JWT 기반 인증, HTTPS 전송, 개인정보 암호화 |
| 운영 | 알림 발송 성공/실패 로깅, 외부 API 호출량 모니터링 |

## 유저 스토리

```
US-01. 유저로서, 매일 정해진 시간에 오늘의 날씨 알림을 받고 싶다.
       → 출근 전에 옷차림을 결정할 수 있도록.

US-02. 유저로서, 앱을 켜자마자 어제 옷차림이 어땠는지 한 번에 답하고 싶다.
       → 피드백이 번거롭지 않아야 매일 기록을 남길 수 있다.

US-03. 유저로서, 추위/더위를 잘 타는 내 체질을 반영한 옷차림을 추천받고 싶다.
       → 동일 기온이라도 사람마다 적정 옷차림이 다르다.

US-04. 유저로서, 외출하지 않은 날은 피드백을 건너뛰고 싶다.
       → "실내에만 있었어요"로 데이터 오염을 막는다.

US-05. 유저로서, 지난 옷차림 기록을 한눈에 보고 싶다.
       → 비슷한 날씨에 뭘 입었는지 회고할 수 있다.
```
